# Data Dictionary

> **The dataset is SYNTHETIC.** It was generated by `src/data/generate_dataset.py` (seed 42) from
> hand-written templates. It is realistic in vocabulary and noise but not real student text.
> See *Limitations* at the end.

## 1. Files

| File | Rows | Description |
|---|---|---|
| `data/raw/tickets_synthetic.csv` | 6,052 | raw generator output, including injected duplicates and empty rows |
| `data/processed/train.csv` | 3,498 | training split (70% of the in-distribution data) |
| `data/processed/val.csv` | 750 | validation split (15%): hyper-parameter / model selection, early stopping |
| `data/processed/test.csv` | 750 | in-distribution test split (15%), used once for final scores |
| `data/processed/test_unseen.csv` | 845 | **unseen-template** test set: tickets from 20 phrasing templates removed *before* splitting |
| `data/ner_gold.json` | 50 tickets | hand-labelled entity gold set for NER evaluation |
| `reports/data_stats.json` | – | cleaning statistics, split sizes, list of held-out templates |

## 2. Columns

| Column | Type | Description |
|---|---|---|
| `ticket_id` | string | unique id, e.g. `TKT102906` |
| `text` | string | raw ticket text as submitted (noise included) |
| `category` | string (label) | one of the 5 categories below |
| `source` | string | channel: `web_form` (45%), `email` (31%), `mobile_app` (20%), `walk_in` (5%) |
| `created_date` | date (ISO) | submission date, Jul–Nov 2026, with seasonality (fee tickets peak Jul/Aug, exam tickets peak Nov) |
| `gen_kind` | string | *generator metadata*: `standard`, `ambiguous` (multi-intent), `vague`, plus `+mislabel` if the label was deliberately flipped. **Never used as a model feature**, only in error analysis |
| `template_id` | string | *generator metadata*: the template a ticket came from (`core:<label>:<k>`, `cross:<k>`, `vague:<label>:<k>`); used for the unseen-template hold-out |
| `text_clean` | string | *processed splits only*: classical-mode preprocessing (for BoW/TF-IDF) |
| `text_light` | string | *processed splits only*: transformer-mode light cleaning (for SBERT/DistilBERT) |

## 3. Label definitions

| Label | Routed to | Covers |
|---|---|---|
| `IT_WiFi` | IT Services | Wi-Fi/internet/LAN, university e-mail, passwords, VPN, Teams/Zoom, software licences, lab PCs, printers, projectors |
| `LMS_Portal` | LMS / ERP Support | LMS/Moodle, student-portal login, course enrolment on the portal, assignment/quiz upload failures, portal profile data |
| `Academics_Exams` | Examination Cell & Academic Office | timetable, hall tickets, results, re-evaluation, attendance, syllabus, backlog exams, certificates |
| `Fees_Accounts` | Accounts Office | fee payment failures, receipts, refunds, scholarships, challans, fines, loan letters |
| `Hostel_Facilities` | Hostel & Estate Office | room allotment, mess, water/electricity, maintenance, library facilities, transport, laundry |

**Boundary rules for overlapping tickets:** the label is the *primary* intent, i.e. the department that must act.
"Fee paid but portal shows unpaid" → `Fees_Accounts`; "cannot login to portal to see my result" → `LMS_Portal`;
"wifi not working in hostel room" → `IT_WiFi`.

## 5. Generation method

1. **Templates:** 133 core templates (~27 per class) plus 20 hand-written cross-department tickets and 25 vague tickets. Inline alternatives `[a|b|c]` multiply the phrasings.
2. **Slot filling** with domain entities: student IDs (`KRM2023MCA045`), course codes (`MCA-301`, `CS204`, `ETMMTI303`), rooms (`Hostel B-212`, `Block C`, `Lab 3`), error codes (`ERR_403`, `E-1021`, `HTTP 500`), amounts (`₹45,000`, `Rs. 2500`, `INR 12500`), transaction IDs (`TXN…`, `UTR…`), dates, times, names, e-mails, phones, URLs.
3. **Composition:** optional greeting, core problem, optional detail, request and sign-off.
4. **Shared vocabulary:** words like *portal, password, payment, library, room, exam* occur in several classes, so no single keyword decides the class.
5. **Multi-intent tickets (10%):** a core problem plus a clause from another department.
6. **Noise (~55% of tickets):** typos (swap/drop/duplicate/replace a character), abbreviations (`pls`, `acct`, `u`, `nt`, `bcoz`), elongations (`pleaseee`), repeated punctuation, missing punctuation, lowercase/UPPERCASE, emojis.
7. **Label noise (1.5%)**, simulating mis-filed tickets.
8. **Injected dirt:** 40 duplicates and 12 empty/missing rows, so the cleaning step has real work.

## 6. Cleaning (`src/data/clean_split.py`)

| Step | Count |
|---|---|
| raw rows | 6,052 |
| missing text removed | 6 |
| blank text removed | 6 |
| exact duplicate rows | 195 (injected + naturally repeated short tickets) |
| texts with conflicting labels | 2 (first occurrence kept) |
| **clean rows** | **5,843** |

Then **20 templates (≈15% per class)** are removed entirely to form `test_unseen.csv` (845 tickets). The remainder is split 70/15/15, stratified by category (seed 42).

## 8. NER gold set (`data/ner_gold.json`)

50 tickets written **independently** of the generator and the extraction rules. Labels: STUDENT_ID, COURSE_CODE, DEPARTMENT, LOCATION, ERROR_CODE, AMOUNT, TXN_ID, SYSTEM, DATE, TIME, PERSON, EMAIL, PHONE (125 entity mentions). It deliberately includes unusual formats (`ERR-504`, `E1021`, `CSE-205`, `Lab-3`, `Hostel D 210`, lowercase IDs, `INR 1,25,000`) so the evaluation exposes real gaps. Annotation guideline: PERSON excludes honorifics; DATE excludes prepositions; relative dates ("yesterday") count as DATE.

## 9. Limitations created by synthetic data

* **Optimistic in-distribution scores.** Train and test share templates, so ~0.985 macro-F1 mostly measures template recognition. The UMAP plot shows one tight cluster per template. The **unseen-template set** is the more honest estimate (0.73–0.91 macro-F1 depending on the model).
* Real tickets are longer, tell stories, mix Hindi and English, and contain screenshots and forwarded threads. None of that is modelled.
* Label noise and ambiguity rates were chosen by us, not measured.
* Entity formats (student-ID pattern, course prefixes) follow our own convention; a real university would need its own patterns.

**Plugging in real data:** see `src/data/load_dataset.py` (map any `text,label` CSV onto the 5 categories), then re-run the pipeline.
